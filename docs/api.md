# API

The HTTP contract between the app and the server — the only agreement between the two projects.
No package, type or file is shared; both sides own their copy of the shape described here.

- **Base URL:** whatever `EXPO_PUBLIC_API_URL` points at in the app
  ([mobile/.env.example](../mobile/.env.example)). The server listens on `0.0.0.0:${PORT}`,
  `PORT` defaulting to `3333`.
- **Format:** JSON, UTF-8. Requests with a body send `Content-Type: application/json`.
- **Authentication:** none. Every route is open to any caller that can reach the port.
- **Vocabulary:** Portuguese, matching the app's domain objects. The database is English and the
  service translates ([ADR 0006](decisions/0006-english-database-portuguese-contract.md)).
- **Source:** [visitante.controller.ts](../server/src/visitors/visitante.controller.ts),
  registered with the prefix `/visitantes` in [server.ts](../server/src/server.ts).

## Types

```ts
type TipoVisita = "visitante" | "entrega" | "prestador";

interface Visitante {
  id: string;            // uuid, generated by the database
  nome: string;
  tipo: TipoVisita;
  dataPrevista: string;  // "YYYY-MM-DD", calendar day, no time and no timezone
  autorizadoPor: string;
}

interface ErrosFormulario {  // only the fields that failed appear
  nome?: string;
  tipo?: string;
  dataPrevista?: string;
  autorizadoPor?: string;
}
```

`createdAt` and `updatedAt` exist in the database but are never exposed.

## `GET /visitantes`

Lists every visitor, ordered by `dataPrevista` ascending, then by creation order
([RN-VIS-06](business-rules.md#rn-vis-06--the-list-is-ordered-by-expected-date-nearest-first)).

| Status | Body |
|---|---|
| `200` | `Visitante[]` — `[]` when there is none |
| `500` | `{ "mensagem": "Internal server error." }` |

```http
GET /visitantes

200 OK
[{ "id": "c286757b-…", "nome": "Jane Smith", "tipo": "visitante",
   "dataPrevista": "2026-09-14", "autorizadoPor": "Carlos" }]
```

## `POST /visitantes`

Registers a visitor. `nome` and `autorizadoPor` are trimmed before storing, and the response
carries the normalized values. Extra fields are ignored, including an `id` sent by the client —
the id always comes from the database.

| Status | Body | When |
|---|---|---|
| `201` | `Visitante` | Saved |
| `400` | `{ "erros": ErrosFormulario }` | One or more rules in [Visitors](business-rules.md#visitors) failed |
| `400` | Fastify's own error shape, without `erros` | Body is not valid JSON |
| `500` | `{ "mensagem": … }` | Unexpected failure |

```http
POST /visitantes
{ "nome": "", "tipo": "morador", "dataPrevista": "2026-02-31", "autorizadoPor": "Ana" }

400 Bad Request
{ "erros": { "nome": "Name is required.",
             "tipo": "Select a visit type.",
             "dataPrevista": "Enter a real date as DD/MM/YYYY." } }
```

The app shows each message under its field without translating anything, which is why the message
text is part of the contract and must stay identical on both sides.

## `DELETE /visitantes/:id`

Removes a visitor permanently. Idempotent: an id that no longer exists also returns `204`
([RN-VIS-07](business-rules.md#rn-vis-07--removing-a-visitor-twice-is-not-an-error)).

| Status | Body |
|---|---|
| `204` | empty |
| `500` | `{ "mensagem": … }` |

## Not in the contract

`GET /visitantes/:id`, `PUT` and `PATCH` do not exist — there is no detail screen and visitors
cannot be edited ([RN-VIS-08](business-rules.md#rn-vis-08--visitors-cannot-be-edited)). Any other
path returns Fastify's default `404`.

There are no routes for condominiums, units, users or memberships yet: those entities are created
only by the [seed script](development.md#sample-data).
