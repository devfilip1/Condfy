# API

The HTTP contract between the app and the server — the only agreement between the two projects.
No package, type or file is shared; both sides own their copy of the shape described here.

- **Base URL:** whatever `EXPO_PUBLIC_API_URL` points at in the app
  ([mobile/.env.example](../mobile/.env.example)). The server listens on `0.0.0.0:${PORT}`,
  `PORT` defaulting to `3333`.
- **Format:** JSON, UTF-8. Requests with a body send `Content-Type: application/json`.
- **Authentication:** every visitor route requires `Authorization: Bearer <access token>`. The
  account and session routes below are the way to obtain one.
- **Vocabulary:** English everywhere — contract, code and database use the same words, so no
  layer translates names ([ADR 0006](decisions/0006-english-database-portuguese-contract.md)).
- **Source:** [visitor.controller.ts](../server/src/visitors/visitor.controller.ts),
  registered with the prefix `/visitors` in [server.ts](../server/src/server.ts).

## Types

```ts
type VisitType = "visitor" | "delivery" | "service_provider";

interface Visitor {
  id: string;            // uuid, generated by the database
  name: string;
  type: VisitType;
  expectedDate: string;  // "YYYY-MM-DD", calendar day, no time and no timezone
  authorizedBy: string;
}

interface FormErrors {  // only the fields that failed appear
  name?: string;
  type?: string;
  expectedDate?: string;
  authorizedBy?: string;
}
```

`createdAt` and `updatedAt` exist in the database but are never exposed.

## Account and session

Types: `Credentials` (`accessToken`, `refreshToken`, `expiresAt`, `refreshExpiresAt`), `User`
(`id`, `name`, `email` — never the password hash) and `Session` (`user` + `credentials`).

| Route | Body | Success | Failures |
|---|---|---|---|
| `POST /accounts` | `{ name, email, password }` | `201` `Session` — signs in right away, account starts with no condominium | `400` `{ errors }` (name, e-mail format, e-mail in use, password under 8 chars) · `429` when the origin created too many accounts |
| `POST /sessions` | `{ email, password }` | `200` `Session` | `401` `E-mail or password is incorrect.` — the same answer for a wrong password and an unknown e-mail · `429` + `Retry-After` after 5 failures |
| `POST /sessions/refresh` | `{ refreshToken }` | `200` `Credentials` — rotates and extends the 30-day deadline | `401` when unknown, expired, or already used — and an already-used one revokes every credential of that user |
| `DELETE /sessions` | `{ refreshToken }` | `204` always — idempotent | — |

The access token carries only `sub`, `iat`, `exp` and `iss`: no role and no condominium
([RN-AUT-05](business-rules.md#rn-aut-05--the-access-token-carries-identity-and-nothing-else)).

## `GET /visitors`

Lists every visitor, ordered by `expectedDate` ascending, then by creation order
([RN-VIS-06](business-rules.md#rn-vis-06--the-list-is-ordered-by-expected-date-nearest-first)).

| Status | Body |
|---|---|
| `200` | `Visitor[]` — `[]` when there is none |
| `401` | `{ "message": "Your session has expired. Sign in again." }` — missing, malformed, tampered or expired token |
| `500` | `{ "message": "Internal server error." }` |

```http
GET /visitors

200 OK
[{ "id": "c286757b-…", "name": "Jane Smith", "type": "visitor",
   "expectedDate": "2026-09-14", "authorizedBy": "Carlos" }]
```

## `POST /visitors`

Registers a visitor. `name` and `authorizedBy` are trimmed before storing, and the response
carries the normalized values. Extra fields are ignored, including an `id` sent by the client —
the id always comes from the database.

| Status | Body | When |
|---|---|---|
| `201` | `Visitor` | Saved |
| `400` | `{ "errors": ErrosFormulario }` | One or more rules in [Visitors](business-rules.md#visitors) failed |
| `400` | Fastify's own error shape, without `erros` | Body is not valid JSON |
| `500` | `{ "message": … }` | Unexpected failure |

```http
POST /visitors
{ "name": "", "type": "resident", "expectedDate": "2026-02-31", "authorizedBy": "Ana" }

400 Bad Request
{ "errors": { "nome": "Name is required.",
             "tipo": "Select a visit type.",
             "dataPrevista": "Enter a real date as DD/MM/YYYY." } }
```

The app shows each message under its field without translating anything, which is why the message
text is part of the contract and must stay identical on both sides.

## `DELETE /visitors/:id`

Removes a visitor permanently. Idempotent: an id that no longer exists also returns `204`
([RN-VIS-07](business-rules.md#rn-vis-07--removing-a-visitor-twice-is-not-an-error)).

| Status | Body |
|---|---|
| `204` | empty |
| `500` | `{ "message": … }` |

## Not in the contract

`GET /visitors/:id`, `PUT` and `PATCH` do not exist — there is no detail screen and visitors
cannot be edited ([RN-VIS-08](business-rules.md#rn-vis-08--visitors-cannot-be-edited)). Any other
path returns Fastify's default `404`.

There are no routes for condominiums, units or memberships yet — only accounts, through
`POST /accounts`. Linking a person to a condominium still happens exclusively through the
[seed script](development.md#sample-data).
