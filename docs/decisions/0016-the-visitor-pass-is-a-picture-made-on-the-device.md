# 0016 · The visitor pass is a picture made on the device, and three libraries came with it

**Status:** Accepted · **Date:** 2026-10

## Context

Feature 012 gave every registered visit a **pass**: a square addressed to the visitor, saying who
authorizes their entry, where and when, with a QR code that belongs to that visit. The resident
shares it through whatever app they already use to talk to the visitor.

It is the first thing the app produces for somebody who is **not a user of it** — opened on a phone
that never had Condfy installed. That raised three questions the project had not met: how to draw a
QR code, how to turn part of a screen into a picture, and how to hand a picture to another app. The
project had gone twelve features without adding a dependency to the app, and Principle V of the
constitution asks for a written justification before one enters `package.json`. This is it.

## Decision

**The pass is drawn on the device, from the visit the list already holds, and turned into a picture
on the device too.** No request is made to open it or to share it.

Three dependencies were added to `mobile/package.json`, each confined to one file:

| Library | For | The only file that imports it |
|---|---|---|
| `qrcode-generator` | Turning a string into the grid of a QR code | [shared/lib/qr.ts](../../mobile/shared/lib/qr.ts) |
| `react-native-view-shot` | Rasterising the pass into a PNG | [passSharing.ts](../../mobile/features/visitors/services/passSharing.ts) |
| `expo-sharing` | Opening the system's share sheet with a file | [passSharing.ts](../../mobile/features/visitors/services/passSharing.ts) |

**The QR is drawn with `View`s**, not SVG: the encoder returns a grid of booleans and a component
paints dark runs.

**The pass is always drawn with the light palette**, whatever appearance the app is in, by nesting
the `ThemeProvider` the app already has with `scheme="light"`. That is not a colour read from a
constant ([ADR 0014](0014-colours-come-from-context-and-styles-are-made-from-the-palette.md) still
holds): every component inside the pass styles itself with `makeStyles` and simply receives the
light palette.

**The QR carries `condfy:pass:<code>` and nothing else.** The code is a column of the visit,
generated by the database (`gen_random_uuid()`), unique, never changed, and sent by the API only to
whoever authorized that visit.

## Alternatives considered

| Option | Why not |
|---|---|
| Write the QR encoder by hand | Several hundred lines of error-correction arithmetic to maintain, and a wrong bit is a pass that does not scan at a gate |
| `react-native-qrcode-svg` | Brings `react-native-svg`, a native module, to draw squares that `View` already draws |
| Render the picture on the server | Needs an image library and fonts on the server to draw what the device is already showing, and makes sharing depend on the network |
| Share a link to a pass page | There is no public page, and a link is not a pass somebody can show at a gate without a connection |
| React Native's own `Share` | Shares text and URLs; on Android it cannot attach a local image |
| Use the visit's `id` as the code | The administrator receives the `id` of every visit of the condominium, and must not hold the code of a visit they did not authorize |
| A fixed set of colour constants for the pass | Exactly what ADR 0014 removed. The nested provider gives the same result without the exception |

## Consequences

- **Opening and sharing a pass work offline**, and the server never sees a finished pass.
- **The shared picture is the same on every device and in both appearances**: it is captured at a
  fixed 1080 × 1080, and its QR is always dark on light.
- **On the web, sharing is not `expo-sharing`'s job.** In a browser that module shares an address,
  not a file. `passSharing.ts` offers the file to the browser directly and, when the browser will
  not share files, **saves** the picture and says so. A Share button that does nothing is the one
  outcome ruled out.
- **Nobody reads a code inside the app yet.** There is no scanner, no gate role and no public page;
  the unique index on `pass_code` is what a later reader will look a code up by.
- **Validity is decided on the device for now** — a pass is "no longer valid" when the visit's day
  is before the device's today. Nothing is accepted or refused on that basis; when a reader exists,
  the server will decide and the label will follow it.
- **The footer's mark is drawn in code.** The repository has no logo file — `app.json` points at an
  `assets/` folder that does not exist. `CondfyMark.tsx` is the one component to change when one
  does.
- **Install with `npx expo install`, never `npm install`**, so the versions match the SDK in use.
  `expo-sharing` also registered itself as a config plugin in `app.json`.
- **Two "only file" rules now exist that the typecheck does not enforce**, and they are recorded in
  `CLAUDE.md`: a second import of any of these libraries is a design question, not a convenience.
